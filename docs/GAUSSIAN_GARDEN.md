# Mip-NeRF 360 Garden — genuine Gaussian Splatting (visual preview)

The **REAL GARDEN · 3DGS** button in the mission studio now displays the public
[Mip-NeRF 360 Garden](https://superspl.at/scene/bc0906cd), reconstructed by
[transkatgirl](https://superspl.at/scene/bc0906cd) from the
[Mip-NeRF 360 dataset](https://jonbarron.info/mipnerf360/). Scene listing:
**CC BY 4.0**, 3.3M Gaussians; original creator attribution and license are
visible inside the application. Credits and the original page must be retained.

## What works

- Genuine photorealistic splat rendering via the official SuperSplat-hosted
  scene in an on-demand iframe; not a screenshot, fake polygon garden or 2D image.
- Viewer loads only after selecting REAL GARDEN, preserving bandwidth on normal
  dashboard access. Orbit/pan/zoom depend on the embedded viewer.
- Existing 3D CAD campus, 2D map, robotics playback, collision diagnostics,
  archived Gazebo evidence and API remain untouched.
- The diagnostic Python server explicitly allows frames from
  `https://superspl.at`; all other existing CSP restrictions are retained.
- Browsing needs an internet connection because splat data is **not shipped
  in Git**, and availability depends on the source host.

## Critical limits — do not misrepresent to the professor

This is **visual embedding**, not a synchronized robotics simulation.
The external SuperSplat viewer is cross-origin: the project's robot mesh,
routes and telemetry do not move inside it. The existing campus occupancy grid
and Gazebo models **do not describe garden surfaces**, and the splat has not been
metrically aligned to the CDR robot coordinate frame.

The existing dashboard replay is generated by a scripted Python campus model,
not Gazebo/Nav2 garden physics. A screenshot showing Garden beside telemetry
does **not** establish that the telemetry was obtained from the garden.

## Future physics integration acceptance gates

1. Download the scene from its owner-enabled SuperSplat page, recording the exact
   source checksum and CC BY 4.0 attribution. A 113 MB scene should not be
   committed into ordinary Git history (GitHub's per-file 100 MB limit).
2. Obtain or reconstruct scale-correct ground and obstacle geometry with
   collision meshes/voxel data. A splat alone has no reliable physics contacts.
3. Register a shared metric transform (origin, scale, orientation) between
   visualization and Gazebo. Verify at least three surveyed point correspondences.
4. Run Gazebo headlessly on the **garden collision mesh**, bridge ROS topics,
   record independent ground truth, simulated odometry/LiDAR, collision outcomes.
5. Use a **single rendering engine** or an explicit scene pose bridge to render
   the physical robot at the correct depth in the Garden; a cross-origin iframe
   cannot support this accurately.
6. Export the recorded run with provenance, seed, world hash and unit test/
   physics validation report before describing it as garden simulation.

```bash
python -m unittest tests.test_gaussian_garden -v
python scripts/serve_dashboard.py
# http://127.0.0.1:8765  ->  REAL GARDEN · 3DGS
```

If the embedded viewer is unavailable or blocked by a browser, use
[the original scene page](https://superspl.at/scene/bc0906cd) linked in
the disclosure. No GitHub Codespaces GPU is needed for this *visual*
embedding; your web browser renders the remote Gaussian splats.
